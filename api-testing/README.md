# 🧪 API Testing

This section contains my API testing work, focusing on validating backend functionality, error handling, and service reliability.  
All tests are designed using real‑world scenarios and follow industry‑standard API testing practices.

---

## 📁 What’s Included in This Folder

- Positive and negative API test cases  
- Status code validation  
- Response body validation  
- Error handling checks  
- Authentication and authorization scenarios  
- Sample API bug reports  
- Environment details (where applicable)  

---

## 🧰 Tools & Technologies Used

- **Postman** – for designing and executing API requests  
- **JSON** – for request/response validation  
- **REST API principles**  
- **HTTP status code analysis**  
- **Environment variables** for reusable test data  

---

## 🔍 Types of Tests Covered

- **Functional tests**  
  Validate correct behaviour of API endpoints.

- **Negative tests**  
  Ensure proper error messages and status codes.

- **Boundary tests**  
  Validate limits such as max/min values.

- **Authentication tests**  
  Token validation, expired tokens, missing tokens.

- **Data validation tests**  
  Schema checks, required fields, incorrect formats.

---

## 🧪 Why API Testing Matters

API testing helps to:

- Validate backend logic  
- Ensure data is processed correctly  
- Catch issues before they reach the UI  
- Support reliable integration between services  
- Improve overall system stability and performance
